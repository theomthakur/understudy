    A

    Architecture & surfaces

    The seams that keep one implementation from painting the design into a corner.

    D1Portability seam

    One Surface interface is the only thing that touches a UI

    Discovery, replay, policy, and escalation depend on an observe / resolve / act interface. Only WebSurface knows Playwright exists.

    Instead of

    Calling Playwright directly from the replay engine, which is faster to write and impossible to extend to desktop.

    Why

    The environment is heterogeneous: modern web, legacy web, native desktop. A desktop implementation supplies the same interface through OS accessibility APIs and nothing above the seam changes.

    src/surface/surface.ts
    D2Observation

    Screenshot for context, numbered accessibility candidates for action

    The model sees a screenshot plus an enumerated list of operable controls. It may only act on a listed candidate; invented selectors and coordinates are ignored by the runtime.

    Instead of

    Feeding raw HTML (huge, brittle, leaks data) or pure screenshot-and-coordinates (resolution dependent, no semantic meaning to record).

    Why

    It works where there is no clean DOM, and it doubles as a guardrail: the model literally cannot name a target the runtime did not offer.

    src/surface/aria-snapshot.ts · src/discovery/prompt.ts
    D3Target choice

    A deliberately hostile synthetic banking console, run locally

    Frameset navigation, nested layout tables, volatile ASP.NET-style IDs, no test IDs, tenant relabeling, and reproducible failure switches.

    Instead of

    A public demo site, which cannot safely or reproducibly produce permission denials, session expiry, or injected hard failures, and carries terms-of-service risk.

    Why

    The interesting states in this brief are the exceptional ones. They have to be deterministic to be testable, and safe to be ethical.

    target-app/
    D4Stack

    TypeScript end to end, Playwright, Zod

    One language across the target app, agent, replay engine, and tests. Playwright provides first-class frame support and lets the evidence script attach a second client to the same live session over CDP. Zod makes the artifact schema executable validation, not documentation.

    Instead of

    Python plus Selenium, or a CUA SDK that hides the loop this brief asks to be shown.

    Why

    The artifact is the product. A schema that validates at runtime means an invalid artifact cannot exist quietly.

    package.json · src/domain/artifact.ts · scripts/curate-evidence.ts
    B

    The artifact

    The brief calls the schema a focal point of the evaluation. These are its load-bearing choices.

    D5Schema shape

    A contract, not a macro recording

    Identity and versioning, typed inputs and outputs with sensitivity, discriminated action steps, semantic descriptors with ordered fallbacks, checkpoints, declared business outcomes, bounded recovery rules, per-step risk, a policy snapshot, tenant overlays, provenance, and a contract hash.

    Instead of

    Persisting the model transcript or a bare step list and replaying that.

    Why

    A human reviewer and a calling agent both need to know what the capability does, needs, and returns without reading a transcript.

    src/domain/artifact.ts
    D6Parameterization

    Only declared inputs become parameters

    During recording, a typed value equal to a declared discovery input becomes a parameter reference. Nothing is generalized because it merely looks similar.

    Instead of

    Heuristic generalization of anything value-shaped, which silently turns coincidences into parameters.

    Why

    A capability whose contract was guessed is worse than one that is honestly narrow. The contract is declared up front and the recorder honors it.

    src/discovery/recorder.ts
    D7Hardening

    The recorder distrusts what the model saw

    The genuine run exposed this: the model read the balance cell by its literal currency text, which would pin replay to one member. The recorder detects volatile value shapes, strips value-shaped fallbacks, and rewrites the target as the relational descriptor: the Balance column in the row containing SAVINGS.

    Instead of

    Trusting the model's locator as recorded and finding out on the second member.

    Why

    The same artifact is proven against a different member and a second tenant. That test only passes because of this step.

    src/discovery/recorder.ts · evidence/curated/replay-second-tenant
    D8Review gate

    Draft until a person approves, and irreversible drafts fail closed

    Discovery always produces a draft. Approval records the reviewer and recomputes the artifact hash. An unapproved irreversible capability refuses to run at all.

    Instead of

    Treating escalation as the safety net for unreviewed automation.

    Why

    Escalation is for runtime surprises. Review is for shipping. Confusing the two lets an unreviewed flow reach a human only after it is already live.

    src/cli.ts · src/domain/artifact.ts · src/policy/policy.ts · src/replay/replay.ts
    C

    Deterministic replay & errors

    The production path. The model is not consulted, so every behavior here had to be designed in advance.

    D9Determinism

    The replay path cannot call a model

    No LLM client import, no prompt, no fallback. Every curated replay records modelInvocations: 0, and tests assert it, including across a human handoff.

    Instead of

    The assisted-fallback stretch goal: a bounded LLM recovery on failure. Considered and rejected.

    Why

    The guarantee is the product. A model with any path back into the decision loop turns a determinism claim into a probability claim.

    src/replay/replay.ts
    D10Locators

    A confidence ladder, not one selector

    Relational table invariant, then exact role and accessible name, then scoped role and name, then explicit recorded fallbacks. The schema permits reviewed CSS or XPath as a last resort, but neither committed capability uses them. Resolution polls only within a bounded timeout.

    Instead of

    Making a raw selector or coordinate the primary locator. The target's volatile ASP.NET-style IDs are specifically built to break that approach.

    Why

    Roles and names are what a human operator actually uses, so they are what survives on legacy markup. Evidence exposes when replay falls to a weaker strategy.

    src/domain/artifact.ts · src/replay/replay.ts · src/surface/web-surface.ts
    D11Result contract

    Four arms: ok, outcome, failed, escalated

    Known business answers such as MEMBER_NOT_FOUND or PERMISSION_DENIED are declared in the artifact and returned as outcomes the caller can branch on. Failures carry step, category, expected versus observed, and evidence.

    Instead of

    Success or exception, where a missing member and a broken locator look identical to the caller.

    Why

    The brief's own glossary says conflating a business outcome with a failure is the most common design mistake here. The taxonomy is the fix.

    src/domain/result.ts
    D12Verification

    Every state transition is checkpointed

    A click succeeding is not evidence the intended state was reached. Navigation and state-transitioning actions declare checkpoints, and the final success condition is itself a checkpoint. Typing and reading do not claim a page transition. Recoveries are explicit artifact data with attempt limits.

    Instead of

    Assuming an action changed state and discovering the truth several steps later, where the evidence no longer points at the cause.

    Why

    Checkpoints are what let a failure report say exactly which expectation broke and what was observed instead.

    src/domain/artifact.ts · src/replay/replay.ts
    D

    Safety & escalation

    The model proposes; the runtime disposes. And when automation stops, control transfer is a lease, not a hope.

    D13Guardrails

    One policy engine for both paths, enforced at the browser layer

    Discovery and replay share the same policy engine. URL policy is exact-host or explicit-suffix. Request interception blocks redirects, frame navigation, click navigation, and popups before they leave the allowlist, and the guard is rechecked after every state-changing action.

    Instead of

    Checking the URL after navigation, which notices the breach only once it has happened.

    Why

    An allowlist that reacts is an audit trail. An allowlist that intercepts is a guardrail.

    src/policy/policy.ts · src/surface/web-surface.ts
    D14Redaction

    Sensitive values are registered before evidence exists

    Sensitive inputs and outputs register with the redactor before any evidence write. Sensitive outputs are recorded as a type, a hash, and a masked proof. Raw HTML, credentials, raw operator keystrokes, and model transcripts are never persisted.

    Instead of

    Scrubbing logs after the fact, which fails exactly once and permanently.

    Why

    This is regulated financial data. The audit stays useful, the value stays out of it, and a verifier script scans the committed evidence for known synthetic sensitive values.

    src/policy/redact.ts · scripts/verify-evidence.ts
    D15Control transfer

    Escalation is a lease transfer on the same live session

    Exactly one actor owns the Surface. The broker runs automation, awaiting human, claimed, released or abandoned. The operator attaches to the same persistent browser context, with cookies, frames, and the prepared form intact, and all automation actions throw until control returns.

    Instead of

    Notification-style escalation, or handing the operator a fresh session that has lost the state the run was stuck in.

    Why

    The brief asks for takeover of the live session specifically. The lease makes who-is-in-control a fact of the system, not a convention.

    src/escalation/escalation.ts · src/escalation/operator-server.ts
    D16Resume

    After release, replay verifies before it trusts

    Human actions are audited without raw typed text, and the operator note is never parsed or allowed to steer execution. On release, replay performs bounded deterministic re-resolution and checkpoint verification, then continues or returns the original failure with intervention linkage.

    Instead of

    Resuming on the operator's word, or letting free-text notes become an unreviewed side channel into the executor.

    Why

    The human completes the step; the checkpoint decides whether it was completed. Those are different facts.

    src/escalation/escalation.ts · src/replay/replay.ts
    E

    Scale & scope

    Designed for the real environment, built as a reviewable slice. The cut lines are decisions too.

    D17Multi-tenant

    Base artifact plus small reviewable overlays

    Tenant reuse is one base artifact plus overlays for entry URLs and descriptor relabeling. The same balance capability replays on Riverbend and on Summitline, where Member ID becomes Member Number, without re-recording. Materially different workflows become separate revisions, not deeper overlays.

    Instead of

    Re-recording per tenant (hundreds of institutions, ~20 apps each), or fuzzy matching that hides drift instead of managing it.

    Why

    Many tenants run the same vendor product configured differently. Overlays absorb configuration drift and stay small enough to review.

    src/domain/artifact.ts · evidence/curated/replay-second-tenant
    D18Scope

    One process, two stretch goals, and named cuts

    Single container so a reviewer runs the whole slice. The production shape is designed and documented: stateless API nodes, isolated session workers, versioned artifact store, append-only events, durable lease queue. Only two stretch directions: the agent-facing capability catalog and cross-tenant reuse. No voice, no CRM, no decorative dashboard.

    Instead of

    Building queues and multi-tenant plumbing the brief explicitly does not reward, or a fourth stretch goal at the cost of depth.

    Why

    Depth over breadth is the stated evaluation. Partially working breadth would weaken the parts that matter.

    01 · The problem

    Banks run software that only a human can operate

    When there is an API, you use the API. This system exists for the long tail that has none: core banking screens, servicing tools, and admin consoles where the only way in is the UI.

    Stable UIs, real runtime errors

    The layout barely changes. What changes is the runtime: validation errors, record not found, permission denials, session expiry, surprise dialogs. A happy-path capability is not useful in production.

    Hostile, legacy surfaces

    Framesets, nested layout tables, volatile server-generated IDs, no test IDs. No clean DOM can be assumed. The only reliable surface is what a human operator sees and does.

    Multi-tenant at scale

    Hundreds of institutions, roughly twenty apps each, many running the same vendor product configured and branded differently. Rebuilding per tenant does not scale.

    Through-line: the model discovers · the artifact becomes a capability · deterministic replay is how an agent invokes it in production.

    02 · Architecture

    Two paths, one shared runtime

    03 · Discovery

    The model is powerful, constrained, and temporary

    Discovery is a genuine LLM loop against the live hostile UI, bounded by step, action, and wall-clock budgets.

    • Observe. A screenshot for visual context plus numbered accessibility candidates: the operable controls, by role and name, across frames.
    • Decide. The model proposes one structured action that must reference a listed candidate. Invented selectors and coordinates are ignored.
    • Act. The runtime, not the model, operates the control, under the same policy engine replay uses.
    • Compile. The recorder turns the successful run into a draft capability, distrusting what the model saw along the way.

    What the genuine run taught the recorder

    The model read the savings balance cell by its literal currency text. Replaying that would pin the capability to one member. The recorder detects volatile value shapes, strips value-shaped fallbacks, and rewrites the target as a relational descriptor: the Balance column in the row containing SAVINGS. The committed second-tenant evidence only passes because of this.

    04 · The artifact

    A contract an agent can call and a person can review

    The artifact is the product of discovery and the input to everything else. The Zod schema validates it at runtime; an invalid artifact cannot exist quietly.

    • Identity. Stable name, schema version, revision, product, supported surface.
    • Contract. Typed inputs and outputs with sensitivity flags and input validation.
    • Behavior. Ordered discriminated steps, semantic descriptors with ordered fallbacks, a checkpoint for every state-changing step.
    • Honesty. Declared business outcomes, bounded recovery rules, per-step risk, policy snapshot, tenant overlays, provenance, contract hash.

    Lifecycle

    Discovered→Draft→Reviewed by a person→Approved→Invoked by agents

    Approval records reviewer identity and recomputes the hash. An unapproved irreversible capability refuses to run: escalation is not a substitute for review. Approved capabilities are exposed to agents as typed tool definitions in the catalog.

    05 · Replay

    Deterministic means the model has no path back in

    The replay engine has no LLM client import, no prompt, and no model fallback. Every curated replay records modelInvocations: 0, and tests assert it, including across a human handoff.

    • Locator ladder. Relational table invariant → exact role and name → scoped role and name → recorded fallbacks. The committed capabilities use no CSS, XPath, or coordinate locators.
    • Bounded waiting. Resolution polls every 250 ms only within a budget; evidence records when a late control needed retries.
    • Checkpoint every state transition. A click succeeding is not evidence the intended state was reached. Typing and reading do not claim a page transition.
    • Guard rechecked. After every state-changing action, the navigation guard is verified before the executor continues.

    Why not assisted fallback

    The brief offers a stretch goal: on replay failure, allow a bounded LLM recovery for one step. It was considered and rejected. The determinism guarantee is the product being sold to a bank; a model with any path back into the decision loop converts a guarantee into a probability. Runtime breakage escalates to a person instead, and the artifact's own bounded recovery rules handle the known interstitials.

    06 · Errors

    Not found is an answer, not a crash

    The result contract has four arms. Conflating a business outcome with a failure is the most common design mistake in this domain, so the taxonomy is the design.

    ok

    The final checkpoint holds and every declared output is returned, typed. Sensitive outputs return as value plus hash and masked proof in evidence.

    outcome

    A declared business answer: MEMBER_NOT_FOUND, NO_SAVINGS_ACCOUNT, PERMISSION_DENIED, SESSION_EXPIRED. The caller branches on a code.

    failed

    Invalid input, policy denial, target drift, exhausted recovery, checkpoint failure, timeout. Carries step, category, expected versus observed, evidence.

    escalated

    A human owns, or abandoned, a still-live intervention. Non-terminal: the run is paused, not dead, and the linkage is recorded.

    Recoveries are explicit artifact data with attempt limits: dismiss a known interstitial, wait out a transient load. Replay never improvises one.

    07 · Escalation

    Control transfer is a lease, not a notification

    • Detect and route. An approved irreversible step, or unresolvable runtime breakage, raises an intervention carrying capability, step, location, screenshot, and reason.
    • Same live session. The operator attaches to the same persistent browser context over loopback CDP: cookies, frames, and the prepared form are provably unchanged.
    • Enforced pause. While a human owns the lease, all automation actions throw. Exactly one actor can ever hold the Surface.
    • Verified resume. Human actions are audited without raw typed text; the operator note is never parsed. On release, replay verifies the step's declared checkpoint before continuing.

    Production gaps are stated, not hidden: authenticated operator identity, durable ownership with heartbeat, streamed remote access, recovery after worker loss.

    08 · Safety

    The model proposes. The runtime disposes.

    Containment

    One policy engine for discovery and replay. Exact-host URL allowlisting with browser-level request interception: redirects, frame navigation, click navigation, and popups are blocked before leaving the allowlist. The action vocabulary itself is allowlisted.

    Risk and review

    Per-step risk is frozen into the reviewable artifact. Draft irreversible capabilities fail closed. Approved irreversible steps follow the configured human policy: the demo routes them through a mandatory intervention.

    Data handling

    Sensitive inputs and outputs register with the redactor before evidence is written. Sensitive currency is recorded as type, hash, and masked proof. Raw HTML, credentials, keys, operator keystrokes, and transcripts are never persisted. A verifier scans committed evidence for known synthetic sensitive values.

    Every record in the target is fabricated. No real customer data, credentials, or third-party banking system is touched anywhere in the project.

    09 · Generalization

    Heterogeneity and hundreds of tenants, by design

    Other surfaces

    Semantic accessibility descriptors work on conventional pages, framesets, and native desktop accessibility trees. The Surface seam means a desktop implementation through Windows UI Automation or macOS Accessibility supplies observe / resolve / act and nothing above it changes. The target already proves frames and nested tables, not just a clean SPA. Coordinates survive only as discovery evidence.

    Other tenants

    One base artifact plus small, reviewable overlays: entry URLs, descriptor relabeling. The committed evidence replays the same capability on Riverbend and on Summitline, where Member ID becomes Member Number, with no re-recording. Overlays absorb configuration drift; materially different workflows become separate artifact revisions.

    The production shape, designed and deliberately not built

    Stateless API nodes; browser sessions pinned to isolated workers scaled by active session count; artifacts in a versioned store; events append-only; screenshots in encrypted object storage; interventions in a durable lease queue. The submission stays one container so a reviewer can run the entire vertical slice, and it does not pretend the in-memory broker is a distributed control plane.

    11 · Cuts

    What was left out, on purpose

    • No breadth theater. No voice interface, CRM, employee task queue, decorative login, or fabricated dashboard. None strengthens the required slice; partially working breadth would weaken it.
    • A deliberately small operator UI. It proves the enforced same-session lease and verified resume; it does not impersonate an institution-grade co-browsing console.
    • Two stretch goals, not five. The agent-facing catalog and cross-tenant reuse. The brief says at most one or two; the rest were declined in writing.
    • No scaling infrastructure. Designed, documented, not built. The brief explicitly does not reward premature plumbing.

    Multi-run stability scoring feeding the approval gate, so draft to approved is earned by replay track record rather than a reviewer toggle alone. Then authenticated operator identity with durable lease ownership. Then a markup-drift test suite that mutates the target and asserts the semantic ladder still resolves.
